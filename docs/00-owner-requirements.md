# Vektor — требования владельца (главнее ТЗ Мануса)

Этот документ дополняет и исправляет `01-manus-spec.md`. При противоречии действует этот документ.

Цель продукта: массовый криптотерминал, максимально близкий по функциональности к Finandy, с понятным для обычного человека интерфейсом.

---

## 1. Интерфейс: понятность важнее количества разделов

### 1.1. Навигация — 6 разделов вместо 14

| Раздел | Что внутри (из разделов Мануса) |
|---|---|
| **Терминал** | график, стакан, панель ордера, позиции и ордера внизу, поиск монеты (бывший Markets), кнопка AI/голос |
| **Позиции** | открытые позиции, ордера, история сделок, результат (бывшие Orders + Positions) |
| **Сигналы и боты** | вебхуки TradingView, Telegram-источники, DCA/Grid, шаблоны (бывшие Signals + Bots & Automations) |
| **Портфель** | балансы по всем биржам, общий результат за выбранный период (бывшие Overview + Portfolio) |
| **Журнал** | что пришло, что сделано, почему отказано (бывший Journal/Audit) |
| **Настройки** | Биржи, Риск-лимиты, Уведомления (Telegram), Безопасность, Язык, Подписка. Команда — позже |

AI Copilot — не раздел, а кнопка в Терминале.

### 1.2. Правила интерфейса

- Каждая вещь живёт в одном месте. Одна и та же цифра не показывается на двух страницах с разными значениями.
- Подписи на языке пользователя, без внутреннего жаргона: не «policy blocked», а «Ордер не отправлен: превышен ваш лимит плеча 10x». Не «preflight», а «Проверка перед отправкой».
- Каждая сумма — с валютой счёта; каждая статистика — с периодом («за 30 дней», «с 1 ноября»).
- Режим счёта всегда виден крупно: ДЕМО / ТЕСТНЕТ / РЕАЛЬНЫЙ.
- Пустой экран всегда говорит, что сделать дальше («Подключите биржу, чтобы видеть баланс» + кнопка).
- Первый вход — 3 шага с прогрессом: почта → биржа → Telegram. Можно пропустить Telegram.
- Панель ордера по умолчанию простая (направление, сумма, плечо, тейк, стоп, кнопка). Всё остальное — под «Расширенные настройки».
- Быстрые кнопки размера: 10 / 25 / 50 / 100% доступного баланса.
- Линии входа, тейков и стопа на графике можно перетаскивать мышью; перед изменением ордера на бирже — подтверждение с новой ценой.
- Горячие клавиши для покупки/продажи/закрытия (настраиваемые, по умолчанию выключены).
- Мобильная версия: позиции, закрытие, перенос стопа, пауза ботов, уведомления. Тяжёлые настройки — только с десктопа или с подтверждением.

## 2. Регистрация и вход — только почта и код

Пароля нет. Один и тот же поток для регистрации и входа:

1. Пользователь вводит почту → «Получить код».
2. На почту приходит 6-значный код.
3. Вводит код → внутри. Если почты не было в базе — аккаунт создаётся автоматически.

Параметры:
- код действует 10 минут, 5 попыток ввода, повторная отправка через 60 секунд;
- ограничение частоты отправки на почту и на IP;
- письмо короткое: код крупно + «если это не вы — просто проигнорируйте»;
- сессия на устройство 30 дней, список устройств и «Выйти везде» в Безопасности;
- 2FA (приложение-аутентификатор) — по желанию, включается в Безопасности; если включена, нужна для вывода в реальный режим и для изменения риск-лимитов;
- никаких обязательных имени, телефона, капчи на первом экране (капча — только при подозрительной активности);
- язык интерфейса определяется автоматически, меняется одним переключателем.

Почта отправляется через провайдера из переменных окружения (Resend или SMTP). Ключи — только в секретах.

## 3. Подключение к любой бирже

Заменяет §14.1 Мануса (там только 5 бирж «и другие после спроса»).

### 3.1. Как устроено

- **Универсальный коннектор на CCXT** — даёт сразу около 100 бирж (спот и фьючерсы, где биржа их отдаёт через API).
- **Нативные коннекторы** поверх него для главных бирж, где нужно больше, чем умеет CCXT (WebSocket ордеров, биржевой трейлинг, хедж-режим): BingX, Binance, Bybit, OKX, Bitget, Gate, MEXC, KuCoin, HTX. BingX — в первую очередь (на нём работает Lucy's Trading Bot, код коннектора можно взять оттуда).
- Пользователь выбирает биржу из списка с поиском. Форма сама показывает нужные поля этой биржи (ключ, секрет, passphrase для OKX/KuCoin/Bitget и т.д.) и ссылку на страницу создания API-ключа на бирже.
- После ввода ключа — автоматическая проверка: ключ работает, есть право торговли, **права на вывод нет** (с правом вывода ключ не принимается), какие рынки доступны.

### 3.2. Честно о возможностях каждой биржи

- Для каждой биржи хранится таблица возможностей (§14.2 Мануса) — заполняется из CCXT и подтверждается тестом.
- В интерфейсе у биржи статус: «Проверена» (прошла все тесты §14.1 Мануса) или «Через универсальный коннектор». Обе можно подключать.
- Если биржа не умеет какой-то ордер сама (трейлинг, несколько тейков, безубыток), терминал ведёт его сам на сервере и прямо пишет об этом у позиции: «Трейлинг ведёт Vektor, не биржа».
- Ограничение, которое нельзя обойти: биржа без торгового API (или без CCXT-поддержки) подключена быть не может — она показывается в списке как «нет API».

## 4. Уведомления в Telegram — как в Lucy's Trading Bot

Заменяет короткий список §20 Мануса. Основа — код `executor/texts.ts`, `executor/telegram.ts`, `lib/subscriber-bot.ts` из Lucy's Trading Bot.

### 4.1. Подключение

- В Настройках → Уведомления кнопка «Подключить Telegram» открывает бота Vektor по ссылке `t.me/<bot>?start=<одноразовый токен>`. Пользователь жмёт Start — чат привязан автоматически, без копирования Chat ID.
- Бот отвечает «Telegram подключён к аккаунту <почта>». Отключить — одной кнопкой там же.

### 4.2. Какие сообщения

Первая строка каждого сообщения: `Источник · Монета · Биржа/счёт` (например `TradingView · SOL · Bybit REAL`). Только простой текст, без HTML.

| Событие | Что в сообщении |
|---|---|
| Позиция открыта | лонг/шорт, вход, объём, плечо, маржа, стоп (% от входа), ликвидация, тейки, кто ведёт позицию, задержка от сигнала до ордера |
| Позиция НЕ открыта | понятная причина: нет монеты на бирже, мало маржи, меньше минимального лота, сигнал устарел, цена уже за стопом, лимит риска, режим позиций не тот — и что сделать |
| Частичная фиксация | сколько закрыто из скольки, при каком % от входа, сколько осталось, где теперь стоп |
| Стоп перенесён | в безубыток / трейлинг подтянут (и что эта прибыль уже защищена) / передвинут вручную или источником |
| Тейк исполнен | какой уровень, прибыль |
| Позиция закрыта | честная причина + вход → выход (средний по частям) + итог в % и в валюте счёта |
| Сигнал отменён источником | именно «отменён», не «стоп-лосс» |
| Ликвидация | отдельно и заметно |
| Защита не встала | «стоп не выставлен — позиция закрыта» (см. 5.2) |
| Биржа | ключ перестал работать, права изменились, связь потеряна/восстановлена |
| Сверка | только если что-то изменилось (расхождение найдено и исправлено). Рутинное «сверка подтверждена» не отправлять |
| Подписка | заканчивается через 3 дня / завтра / закончилась |

Правило названия закрытия (из Lucy's Trading Bot): причина определяется по двум фактам — почему стоп стоял там, где стоял (начальный / безубыток / трейлинг / передвинут источником), и реальный результат исполнения. Стоп, подтянутый в прибыль, никогда не называется стоп-лоссом. В пределах ±0,3% от входа — «безубыток».

### 4.3. Доставка

- Каждое сообщение сначала сохраняется в очередь (outbox), потом отправляется по порядку, не чаще 1 в секунду на чат; на 429 ждать `retry_after`; сетевые ошибки — повтор. Сообщение не теряется молча.
- Отклонённые Telegram сообщения видны в Настройках → Уведомления с ответом Telegram.
- Пользователь включает/выключает группы событий и тихие часы. Ликвидация, «защита не встала» и «ключ не работает» приходят всегда, даже в тихие часы.
- Язык сообщений = язык аккаунта (RU/EN).

## 5. Повторить Finandy полностью

§16 Мануса делает из Finandy только «слой совместимости вебхуков». Это недостаточно: цель — весь функционал Finandy как основной продукт (P0), а не надстройка.

### 5.1. Обязательно в первой рабочей версии

- Ручной терминал: спот и фьючерсы, лимит/маркет/стоп, хедж и односторонний режим, изолированная/кросс маржа, плечо.
- Несколько тейков с распределением объёма в %, стоп, трейлинг, безубыток (после TP1 / после % движения), частичное закрытие, разворот позиции, закрыть всё.
- **Управление позициями, открытыми не через терминал** (вручную на бирже или другим ботом): терминал их видит и позволяет навесить тейки/стоп/трейлинг.
- Шаблоны настроек сделки (размер, плечо, тейки, стоп, трейлинг) — выбрать шаблон в один клик, применить к сигналу.
- Сигнальные боты: вебхук TradingView и свой POST-запрос с JSON; открыть / усреднить / закрыть / развернуть / хедж; параметры сделки внутри сигнала; изменение настроек бота из сигнала.
- DCA / страховочные ордера с пересчётом средней и перестановкой тейков и стопа.
- Размер позиции: фиксированная сумма, % от депозита, по риску до стопа.
- Тестовая отправка сигнала, повтор сигнала, защита от дублей, срок жизни сигнала (§9.5 Мануса).
- Метки на графике: сигнал, вход, тейки, стоп, частичные выходы, закрытие.

### 5.2. Правила из Lucy's Trading Bot, которые переносятся как есть

- Безубыток = собственный ноль пользователя (его реальный вход + комиссии), никогда не ниже входа.
- Если позиция открылась, а стоп выставить не удалось (или ликвидация оказалась раньше стопа и долить маржу не получилось) — позиция закрывается, пользователь получает сообщение.
- Ликвидация должна быть дальше стопа; если нет — предупредить до отправки ордера.
- Сообщения и журнал описывают то, что реально случилось, по фактическим исполнениям биржи, а не по типу ордера.
- Ордер на вход, который мог дойти до биржи, ищется по его id — второй никогда не отправляется.
- Сверка позиций с биржей идёт постоянно; найденное расхождение исправляется и сообщается.
